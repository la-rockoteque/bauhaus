# Badge

The Showcase story holds the tokens, the anatomy, the states grid, the live rulebook and the accessibility coverage. This guide holds the reasoning.

## 1. Introduction

**In plain words:** A badge is a small pill that shows a number, such as 3 unread, or a status word, such as Paid.

**Precisely:** Component in the feedback family. It shows a count or a status on a solid fill. The badge, the chip and the tag are different things: a badge marks a count or status, a chip filters or takes input, a tag labels a category (`knowledge/components/catalog.md`). This slice is the badge only.

**The job.** A badge lets the user scan for the thing that needs attention without opening it.

## 2. Usage

### How

- **Status.** Each status has its own fill and text role, `badge.<status>` and `badge.<status>-text`. The text reaches 4.5:1 on the fill in both themes (WCAG 1.4.3 Contrast, AA). A status badge must carry a word. "Overdue" tells the user what red only hints (WCAG 1.4.1 Use of Color, A).
- **Count cap.** A count above `max` shows as "99+". The pill stays small, and the layout does not break for large numbers. The visible text is hidden from assistive technology and a hidden text holds the full number, so a screen reader says "142", not "ninety-nine plus" (WCAG 4.1.2 Name, Role, Value, A). Raise or lower `max` for a narrow space: `max={9}` gives "9+".
- **Say what it counts.** A bare "3" is a number with no noun. Pass `label="unread messages"` and the accessible text reads "3 unread messages" (WCAG 2.4.6 Headings and Labels, AA). If the noun is already in the text beside the badge, use `decorative` instead.
- **Decorative.** When adjacent text says the same thing ("12 unread messages" beside a badge showing 12), pass `decorative`. The badge gets `aria-hidden` and the fact is read once. Do not use `decorative` when the badge carries information that nothing else does.
- **Zero.** Hide the badge at zero unless zero matters. A "0" invites a look and gives nothing.
- **Live updates.** A badge does not announce its own change. If a change must be spoken, the caller writes it in a polite status message (WCAG 4.1.3 Status Messages, AA).
- **Not a control.** A badge is not pressable, so the 44px target floor does not apply to it. A thing to press, remove or filter by is a button or a chip, with its own target.

## 3. Why the states look as they do

- **Nothing, one, some, too many** are counts of 0, 1, 24 and 142. The last one shows the cap.
- **Incorrect and correct** are the error and success statuses, each with a word.
- **Loading and done** are n/a. A badge shows a known value; the caller omits it until the value exists, and swaps the status when the work ends.
- **All interaction states** are n/a for the reason above.
- **Forced colors.** A 1px border in the system text colour keeps the pill visible when fills are replaced.

## 4. Pitfalls and don'ts

- **Do not use colour alone.** (WCAG 1.4.1, A; `badge.not-colour-alone`)
- **Do not drop the full number.** A capped label alone loses data. (WCAG 4.1.2, A; `badge.count-cap`)
- **Do not leave a number with no noun.** (WCAG 2.4.6, AA; `badge.count-labelled`)
- **Do not read the same fact twice.** (WCAG 1.1.1, A; `badge.decorative`)
- **Do not make a badge pressable.** (WCAG 2.5.8, AA; `badge.not-a-control`)
- **Do not write a colour literal in `badge.css`.** (`misfile.raw-value-in-component`; `badge.no-literal`)
