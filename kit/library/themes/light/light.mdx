# Light theme

## 1. Introduction

**In plain words:** The light theme gives every role a value for a light page. It is the default: it also renders as `:root`, so a page with no `data-theme` looks like this.

**Precisely:** Theme · a full set of role values, sibling of `themes/dark` · defines every role name in `foundations/color` and adds none · components do not change.

## 2. Tokens (defined)

| Token group | Tier | Value |
|---|---|---|
| `text.*` | semantic | Dark neutrals: `colors.neutral.900` default, `600` muted; `text.link` is `colors.primary.700` |
| `surface.*` | semantic | `colors.neutral.100` for default and raised, `200` for sunken |
| `border.*` | semantic | `colors.neutral.300` default, `500` strong |
| `action.*` | semantic | `colors.primary.600` and `colors.secondary.600`, darker for hover and pressed, light label |
| `status.*` | semantic | `600` of each status scale for text and icon, `100` for the surface |
| `focus.ring.color`, `disabled.*`, `state.*` | semantic | `colors.primary.600`; light neutrals; light primary tints |

## 3. Anatomy

One file, `light.tokens.json`. Each role aliases a `colors.*` grade. The theme never aliases the palette and never holds a raw value.

## 4. States

The theme is a state of the whole page: light or dark. Pair contrast is checked in both: `pairs.json` in `foundations/color` lists every pair, and the check runs once per theme. Forced-colors and high-contrast modes are n/a here: they replace author colours and are handled by the browser.

## 5. Usage

### When to use

- As the default. Users who set no preference get this theme.

### When not to use — and what instead

- For a brand variant or a per-customer look: change `colors.tokens.json`, or add a sibling theme that defines every role. Do not stretch this one.
- For one light panel on a dark page: pin `data-theme="light"` on that element.

### How

- Keep the role names identical to `themes/dark`. The check fails on a missing or extra role (Carbon: "Color token names and roles are the same across themes").
- Alias `colors.*` only. The check warns on `palette.*`.
- Re-check every pair at 4.5:1 and 3:1 after a change (WCAG 1.4.3 and 1.4.11, AA).

## 6. Pitfalls and don'ts

| Don't | Why it fails | Basis | Rule id |
|---|---|---|---|
| A role in `light` that `dark` lacks | The build fails: themes are full sets of the same roles | Bauhaus `tokens.mjs check` | `color.theme-parity` |
| A hex value in the theme file | A rebrand cannot reach it | Bauhaus naming lint | `color.roles-alias-colors` |
| A colour literal in a component "for light mode" | The token system is bypassed and the dark theme drifts | Bauhaus `misfile.raw-value-in-component` | `color.semantic-by-intent` |
