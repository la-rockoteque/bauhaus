# The library — contract

Bauhaus builds a design system as **one library package, isolated from the app**. The folders follow screaming architecture and vertical slices: the tree says what the design system contains, and each thing lives in one folder with everything that belongs to it.

`knowledge/architecture/` holds the reasoning and the alternatives. This file is the rule.

## The shape

```
packages/design-system/                 one package, one version, one public entry
├─ package.json                         name, exports, peerDependencies
├─ dist/                                build output; dist/tokens.css is generated by tokens.mjs
├─ index.ts                             the public API; the app never deep-imports
├─ .storybook/                          main.ts globs ../**/*.stories.tsx and ../**/*.mdx
├─ foundations/
│  ├─ color/        color.tokens.json · color.mdx · color.stories.tsx · color.rules.ts
│  ├─ spacing/      spacing.tokens.json · spacing.mdx · spacing.stories.tsx · spacing.rules.ts
│  └─ typography/ motion/ elevation/ shape/ iconography/ density/ focus/
├─ themes/
│  └─ dark/         dark.tokens.json · dark.mdx · dark.stories.tsx
├─ primitives/                          base building blocks other components are built from
│  ├─ box/  text/  icon/  visually-hidden/
│  └─ text/         text.tsx · text.css · text.stories.tsx · text.test.tsx · text.mdx · text.rules.ts
├─ components/
│  ├─ clickables/   button/ icon-button/ link/ menu-item/   · use-press.ts (shared by clickables)
│  ├─ fields/       text-field/ select/ combobox/ checkbox/ radio-group/ switch/
│  ├─ data-structures/  table/ list/ tree/
│  ├─ feedback/     toast/ banner/ spinner/ skeleton/ empty-state/
│  ├─ overlays/     dialog/ popover/ tooltip/ menu/
│  └─ navigation/   tabs/ breadcrumb/ pager/
└─ patterns/
   ├─ filtering/    filtering.mdx · filtering.stories.tsx · filtering.rules.ts
   └─ empty-results/
```

## The layers and where they live

The layers are **foundation · token · component · pattern**. Folders follow them.

| Layer | Lives in | Notes |
|---|---|---|
| Foundation | `foundations/<name>/` | The slice holds the scale's page, stories, rules and **all tiers of its tokens**. |
| Token | `<slice>/<name>.tokens.json` | Primitive and semantic tokens in the foundation slice. Component tokens, if any, in the component slice. Theme overrides in `themes/<name>/`. |
| Component | `primitives/<name>/` or `components/<family>/<name>/` | A primitive is a component other components are built from. It is not a separate layer. |
| Pattern | `patterns/<name>/` | Composes components. Has no tokens and no styles of its own. |

"Primitive" means only two things: the **primitive-token** tier, and the `primitives/` folder of base building blocks.

## The slice

A slice is one folder per thing. It holds every file about that thing, named after it:

| File | Holds | Required |
|---|---|---|
| `<name>.tsx` | The component (framework file: `.vue`, `.svelte`, `.ts` for a custom element). | Component, primitive |
| `<name>.css` | Its styles. Semantic tokens only; no literals. | If it has styles |
| `<name>.stories.tsx` | One story per designed state-matrix cell. | Every slice |
| `<name>.mdx` | The page contract: introduction, tokens, anatomy, states, usage, pitfalls and don'ts. | Every slice |
| `<name>.rules.ts` | Its rulebook entries. | Every slice |
| `<name>.test.tsx` | Behaviour and accessibility tests. | Component, primitive |
| `<name>.tokens.json` | Tokens this slice defines. | Foundation; theme; component only if it has component tokens |
| `<part>.tsx` | A part that cannot stand alone (dialog header, field label). | As needed |

Delete a slice folder and the thing is gone everywhere. That is the test of a good slice.

## Naming rules

1. **The root folders are the only type-named folders.** `foundations/`, `themes/`, `primitives/`, `components/`, `patterns/` (plus the build output `dist/` and `.storybook/`), and the component families inside `components/`. Nothing else may be named for a kind of file.
2. **No nonsignificant folders.** Never `hooks/`, `utils/`, `helpers/`, `lib/`, `common/`, `shared/`, `misc/`, `types/`, `constants/`, `styles/`, `stories/`, `assets/`, `core/`.
3. **Shared code rises to the nearest common ancestor.** A hook used by one component sits beside it. Used by the whole family: at the family level (`components/clickables/use-press.ts`). Used across families: at the root, still named for what it does (`use-controllable-state.ts`), never grouped in a folder by kind.
4. **Names are kebab-case, singular, and name the thing.** Folder `text-field/`, files `text-field.tsx`, `text-field.stories.tsx`. The exported symbol is `TextField`.
5. **A family exists when it has 2 or more members.** One member sits in the closest existing family, or in a new one when the fifth member arrives. The default families are clickables, fields, data-structures, feedback, overlays, navigation. A project may add `layout` for Stack or Grid components.
6. **Storybook's sidebar mirrors the tree.** `title` is derived from the path: Foundations/Spacing, Primitives/Text, Clickables/Button, Patterns/Filtering.

## Isolation rules

1. **The library never imports the app.** No relative path out of the package, and no app path alias.
2. **One public entry.** `index.ts` plus an `exports` map. It also exports `./tokens.css`, which holds `:root` and one `[data-theme="<name>"]` block per theme, so a consumer on another stack uses tokens without the React code.
3. **Framework and runtime are peer dependencies.** React is one of them.
4. **No app concern inside.** No i18n library, router, data fetching, feature flags or auth. Text arrives as props. Links arrive as a render prop or an `as` prop.
5. **Import direction is enforced in CI:**
   - `foundations/` and `themes/` import nothing;
   - `primitives/` imports foundations and other primitives;
   - `components/` imports foundations, primitives and other components;
   - `patterns/` imports components and primitives;
   - nothing imports `patterns/` except the app.
6. **The package tests, builds and runs Storybook alone.** `npm test`, `npm run build` and `npm run storybook` work from inside the package with the app absent.

`scripts/structure.mjs check` asserts the naming rules, the slice rules and the isolation rules.

## Extraction from an app

The library grows beside the app, one slice at a time. There is no big-bang move.

1. **Scaffold** the package (`/bauhaus:library init`). The app depends on it through the workspace.
2. **Tokens first.** Move the token source into `foundations/*` and publish `tokens.css`. The app imports it once.
3. **One component per batch.** Create the slice, move the code, cut every app import (i18n, router, API) into props, write the story, page and rules.
4. **Leave a shim.** The old app path re-exports the library component, marked deprecated. A ratchet counts shims and in-app duplicates: the count may not rise, and it must be lowered when it drops.
5. **Delete the shim** when its last import moves.
6. **Patterns last,** once their components are in the library.

`scripts/structure.mjs place` proposes a target slice for every component found by the analyser.
