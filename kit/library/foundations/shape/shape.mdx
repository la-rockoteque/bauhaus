# Shape

The Showcase story holds the radius tiles. The Advisories story holds the live rulebook and the accessibility coverage. This guide holds the reasoning.

## 1. Introduction

**In plain words:** Shape is how round the corners are. Sharp corners feel strict, round ones feel friendly. The library picks one for controls and keeps it.

**Precisely:** Foundation. A radius scale and one semantic token for controls. It covers corner radius only.

**The job.** One edit to `radius.control` reshapes every control, so shape stays a system decision and never a local one. `radius.full` serves pills and circles.

## 2. Usage

### When to use

- Read `radius.control` for anything the user presses or types into (project decision: one shape for all controls).

### When not to use, and what to use instead

- **To show a boundary.** A radius is not a border. Use `border.*` (WCAG 1.4.11 Non-text Contrast, AA).

### How

- **Nesting.** Nested rounded boxes use a smaller radius inside than outside, so the gap looks even (optical alignment; project decision).
- **Boundary.** Keep a visible border on any control whose fill is under 3:1 against its surroundings (WCAG 1.4.11, AA).

## 3. Why the states look as they do

Radius does not change with interaction. The focus ring follows the corner because the outline is drawn on the same box, so it needs no separate shape.

## 4. Pitfalls and don'ts

- **Do not write `border-radius: 6px` in a component.** It is off the scale, and controls stop matching. (Closed scale; `shape.controls-use-control-radius`)
- **Do not use a borderless pale button on a white page.** The button edge disappears for low-vision users. (WCAG 1.4.11, AA; `shape.boundary-visible`)
