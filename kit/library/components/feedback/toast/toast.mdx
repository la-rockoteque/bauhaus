# Toast

The Showcase story holds the tokens, the stage and the state matrix. The Advisories story holds the live rulebook and the accessibility coverage. This guide holds the reasoning.

## 1. Introduction

**In plain words:** A toast is a small message that slides in to say that something happened, such as "Draft saved", and goes away by itself. It never grabs your keyboard focus.

**Precisely:** Component in the feedback family. `ToastRegion` renders two live regions and the stack of toasts. `useToast` holds the list. No library sits behind it: the toast live region is a simple APG pattern with no native element.

**The job.** A toast confirms a low-stakes result without blocking the user. The user reads it or ignores it.

**When it exists.** Use a toast for saved, sent, archived, copied. Use a banner for a message the user must be able to reread. Use a dialog for a decision.

## 2. Usage

### Wiring

```tsx
const { toasts, show, dismiss } = useToast();
// once, near the root:
<ToastRegion toasts={toasts} onDismiss={dismiss} />
// anywhere you hold `show`:
show({ status: 'success', message: 'Draft saved.' });
```

### How

- **Two live regions.** Screen readers announce content added to a live region that already exists. The region therefore stays in the page, empty, and toasts are added to it. Info, success and warning go to the polite region (`role="status"`), which waits for a pause in speech. Errors go to the assertive region (`role="alert"`), which interrupts (WCAG 4.1.3 Status Messages, AA; APG Alert pattern).
- **No focus.** A toast never takes focus. Focus stays where the user works (WCAG 3.2.1 On Focus, A). Its buttons are in the tab order, in document order, so a keyboard user can reach the action.
- **Time.** The default is 5000 ms and the value is a prop, so the product can adjust it (WCAG 2.2.1 Timing Adjustable, A). Long messages need more time: about 200 ms per word is a fair floor. A toast with an action, or with `duration: null`, stays until the user closes it, because a user cannot be rushed through a decision.
- **Pause.** The timer stops while the pointer is over the toast or focus is inside it. It resumes with the time left, not a fresh five seconds (WCAG 2.2.1, A; WCAG 1.4.13 Content on Hover or Focus, AA).
- **Stack.** At most `max` toasts show, three by default. The rest wait and take a slot as one closes, so their timers start when the user can see them. A "+N more" chip says how many wait. Too many toasts is a sign that some should be a banner or a summary.
- **Content.** Put the result first. Say the object: "Draft saved", not "Success". Keep it under about 15 words. A toast cannot hold a form.
- **Errors.** A toast is never the only place for an error. It vanishes, and a user who missed it has no way back. Repeat the error where the user can find it (`toast.not-sole-error`; WCAG 3.3.1, A).

## 3. Why the states look as they do

- **Some** shows a title, a message and an action. The action makes the toast persistent.
- **Too many** stacks up to `max` and counts the rest.
- **Incorrect** is an error toast in the assertive region, with a stronger border. The icon and the word carry the status, not the colour.
- **Done** is the exit: a fade with a short drop, then the id leaves the list. The exit runs before the removal so the eye can follow it.
- **Hover and focus** both pause the timer. The edge gets stronger so the user sees that the toast waits. Focus-visible is the ring on the toast's own buttons.
- **Reduced motion.** The rise and the drop go; the fade stays. A change of opacity is not motion (WCAG 2.3.3, AAA; `foundations/motion.md`).
- **Nothing, loading, none, one, active, disabled, selected** are n/a. A toast is a finished message, not a control.

## 4. Pitfalls and don'ts

- **Do not move focus to a toast.** The user loses their place. (WCAG 3.2.1, A; `toast.no-focus-steal`)
- **Do not auto-close a toast with an action.** (WCAG 2.2.1, A; `toast.no-timer-with-action`)
- **Do not ignore hover and focus.** A toast that leaves while the user reads it fails. (WCAG 2.2.1, A; `toast.pausable`)
- **Do not create the live region with the message.** Some readers miss content in a region that is new. (`toast.announced`)
- **Do not use a toast as the only copy of an error.** (WCAG 3.3.1, A; `toast.not-sole-error`)
- **Do not slide under reduced motion.** (WCAG 2.3.3, AAA; `toast.reduced-motion`)
