# Button

The Showcase story holds the tokens, the stage and the state matrix. The Advisories story holds the live rulebook and the accessibility coverage. This guide holds the reasoning.

## 1. Introduction

**In plain words:** A button is the thing you press to make something happen. Save, send, delete. If pressing it takes you to another page, it is a link, not a button.

**Precisely:** Component in the clickables family. It triggers one action in the current view. It does not navigate, and it does not toggle a setting.

**The job.** A button answers the question "what can I do here?". Each view region has one main answer, so the button comes in four variants that rank the answers: primary, secondary, tertiary, subtle. Rank is the only thing a variant changes. State (disabled, loading) is a separate prop, so a button can be secondary and loading at once.

**The layer.** The button is a component. It reads roles and semantic tokens. It owns no colour, no size and no radius of its own.

**When it exists.** Use the button when an action needs a control. If the destination is a URL, use a link. If the control keeps a state after the press, use a switch or a checkbox. If the control shows an icon and no text, use the icon button, which forces an accessible name.

## 2. Usage

### When to use

- To trigger an action in place: submit, save, open a dialog, confirm. The WAI-ARIA APG Button pattern defines a button as a control that performs an action.

### When not to use, and what to use instead

- **To go to another page or URL.** Use a link. The role must match the behaviour (WCAG 4.1.2 Name, Role, Value, A).
- **To turn a setting on or off.** Use a switch or a checkbox (APG Switch and Checkbox patterns).
- **For an icon with no visible text.** Use the icon button, which requires an accessible name (WCAG 1.1.1 Non-text Content, A).

### How

- **Variants.** Show one primary per view region. Make the other actions secondary or tertiary. Use subtle for chrome that must stay quiet, such as a toolbar or a segmented control. Choice time grows with the number of options (Hick 1952), and extra emphasis competes with the important item (Nielsen heuristic 8).
- **Height and padding.** The button draws at `size.control.md`, 32px, with a label at `text.label` (14px). Its `padding-block` is 0 and its `padding-inline` is `space.inline.md`, so the block padding stays below the inline padding (`button.padding-flat`). The label sits centred in the 32px box.
- **Content.** Start the label with a verb and name the object: "Save changes". A label describes its purpose (WCAG 2.4.6 Headings and Labels, AA).
- **Keyboard.** Space and Enter activate the button. The component renders a native `button`, so this needs no code (APG Button pattern).
- **Target size.** The button draws at `size.control.md` (32px). The target is at least 24 by 24 CSS px, `size.target.min` (WCAG 2.5.8, AA). 24px is the house floor. No invisible layer is needed.
- **Loading.** Keep the label and the width. Ignore repeat presses. Keep the button focusable. Announce the result somewhere else in the view (Nielsen heuristic 1, visibility of system status; WCAG 4.1.3 Status Messages, AA).
- **Disabled.** A disabled button is exempt from text contrast (WCAG 1.4.3 exception for inactive components). Say why, next to the button (Nielsen heuristic 1).
- **Responsive.** Let the label wrap. Never truncate it (WCAG 1.4.10 Reflow, AA).
- **Form use.** The default `type` is `button`. A button in a form does not submit it unless you pass `type="submit"` (HTML form submission behaviour).
- **i18n.** The label arrives as `children`. The component holds no text of its own (`docs/library.md`, isolation rule 4).

## 3. Why the states look as they do

- **Hover and pressed** use a state layer (`state.hover-layer`, `state.pressed-layer`) on the secondary, tertiary and subtle variants, and a darker fill on the primary. Each differs from its base in lightness, so no state relies on hue alone (WCAG 1.4.1 Use of Color, A).
- **Focus-visible** draws an outline offset from the box. The offset keeps the ring visible against the primary fill, where a ring of the same colour would vanish (WCAG 1.4.11 Non-text Contrast, AA). Mouse presses do not show it.
- **Disabled** uses the disabled roles and the native `disabled` attribute. The attribute removes the button from the tab order and blocks the click, and no ARIA needs to imitate it. The state reads as unavailable, so the view must say why (Nielsen heuristic 1).
- **Loading** hides the label with `opacity`, not `display`. The label keeps its width, so the layout does not jump. It stays in the accessibility tree, so the button keeps its name (WCAG 4.1.2, A). `aria-busy` tells assistive technology that work is running.
- **Too many** wraps the label. A truncated label hides the object of the action (WCAG 1.4.10, AA).
- **Nothing, none, one, some, incorrect, correct, done** are n/a. The button holds no data. The form owns the error and the view owns the confirmation, so the button stays pressable and the user can retry.

## 4. Pitfalls and don'ts

- **Do not write `outline: none` with no replacement.** Keyboard users lose their place. (WCAG 2.4.7, AA; `button.focus-ring`)
- **Do not use a `div` with a click handler.** It has no focus, no Space or Enter, and no role. (APG Button; WCAG 4.1.2, A; `button.native-element`)
- **Do not write `variant="disabled"`.** A state modelled as a choice cannot combine with the variants. (Bauhaus `misfile.state-as-variant`; `button.states.not-variant`)
- **Do not put two primary buttons side by side.** Users cannot tell which action leads. (Hick 1952; Nielsen heuristic 8; `button.one-primary`)
- **Do not swap the label for a spinner while loading.** The width shifts and the name disappears for assistive technology. (Nielsen heuristic 1; WCAG 4.1.2, A; `button.state.loading`)
- **Do not write a colour literal in `button.css`.** The dark theme cannot reach it. (Bauhaus `misfile.raw-value-in-component`; `button.no-literal`)
- **Do not label a button "Click here".** The label names no action and no object. (WCAG 2.4.6, AA; `button.label-verb`)
