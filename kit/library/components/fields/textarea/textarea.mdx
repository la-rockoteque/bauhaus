# Textarea

The Showcase story holds the tokens, the anatomy, the states grid, the live rulebook and the accessibility coverage. This guide holds the reasoning.

## 1. Introduction

**In plain words:** A textarea is a text field with room for several lines: a message, a comment, an address. It grows with what you write and you can drag its corner to make it taller.

**Precisely:** Component in the fields family. It captures multi-line text with a native `textarea`, a visible label, an optional description, an optional counter and an optional error. It does not take one line (use the text field).

**The layer.** A component. It shares the box, label, description and error with the rest of the family (`fields/field.css`), and adds only the resize behaviour and the counter.

## 2. Usage

### When to use

- For text longer than one line: messages, comments, notes.

### When not to use, and what to use instead

- **For one line.** Use the text field, which suits a name or a code.
- **For formatted text.** A rich-text editor is out of scope for this family.

### How

- **Label, description, error, required.** As the text field: a visible label, help tied with `aria-describedby`, error text with an icon and `aria-invalid`, and the word "(required)" (WCAG 3.3.1, 3.3.2, A).
- **Height.** The box is sized by `rows` (default 4) and has a minimum of one control height. It resizes vertically, so a person who zooms to 200% or writes more can see all of the text. A fixed height cuts text off (WCAG 1.4.4 Resize Text, AA; WCAG 1.4.10 Reflow, AA).
- **Counter.** Pass `maxLength` and `count` to show "count / maxLength". The counter joins `aria-describedby`, so a screen reader reads it when the user asks for the description. It is not a live region: announcing the length on every key stroke would talk over the typing. Announce the limit itself in the description ("At most 200 characters") so it is known before the user reaches it (WCAG 3.3.2, A; WCAG 4.1.3, AA).
- **Native limit.** `maxLength` is the native attribute, so the browser stops the input at the limit. Do not truncate the value in script.
- **Enter.** Enter adds a line, as expected. Submit with a button, not with Enter.
- **Paste.** Never block paste.

## 3. Why the states look as they do

- **Hover, focus-visible, invalid, disabled, read-only** follow the text field, because the box is shared. See the text field guide for the reasoning.
- **Too many** scrolls inside the box. The user can drag the corner to see more.
- **Read-only** keeps the text selectable and focusable so a person can copy it.
- **Loading, none, one, done, active, selected** are n/a for the same reasons as the text field.

## 4. Pitfalls and don'ts

- **Do not use the placeholder as the label.** (WCAG 3.3.2, A; `textarea.visible-label`)
- **Do not fix the height or hide the resize handle.** Text is cut at 200% zoom. (WCAG 1.4.4, AA; `textarea.resizable`)
- **Do not announce the counter on each key.** It talks over the typing. (WCAG 4.1.3, AA; `textarea.counter-bound`)
- **Do not show an error by colour alone.** (WCAG 1.4.1, A; `textarea.error-bound`)
- **Do not write a colour or px literal in the stylesheet.** (Bauhaus `misfile.raw-value-in-component`; `textarea.no-literal`)
