# Menu

The Showcase story holds the tokens, the stage and the state matrix. The Advisories story holds the live rulebook and the accessibility coverage. This guide holds the reasoning.

## 1. Introduction

**In plain words:** A menu is a short list of actions that opens from a button. Press the button, pick one action, and the list closes. Arrow keys move, and typing a letter jumps to a match.

**Precisely:** Component in the overlays family. It is React Aria's `MenuTrigger` and `Menu`, styled with tokens, following the WAI-ARIA APG Menu Button pattern. Its items are the menu item slice. It is not site navigation and not a form control.

**The job.** A menu keeps rare or secondary actions out of the way until they are needed, and keeps them in one place.

**The layer.** The menu is a component. It composes the menu item, the icon and the separator.

## 2. Usage

### When to use

- Row actions, a More button, a view switcher, a sort order.

### When not to use, and what to use instead

- **For site navigation.** Use a `nav` with a list of links. `role="menu"` promises application-menu behaviour that navigation does not have (APG Menu Button).
- **For one action.** Use a button.
- **For a form choice with a visible value.** Use a select.
- **For rich content.** Use a popover.

### How

- **Keys.** Enter, Space or Down on the button opens the menu and focuses it. Up opens on the last item. Arrows move and wrap. Home and End jump. A letter jumps to the next label that starts with it, and several letters typed together match a longer prefix. Enter or Space acts. Escape closes the menu and returns focus to the button (APG Menu Button; WCAG 2.1.1, A).
- **One tab stop.** The button is the tab stop. Focus inside the menu moves by arrows only. Tab closes the menu.
- **Semantics.** The button gets `aria-haspopup` and `aria-expanded`. The list has role `menu`, named by `label`. Items get `menuitem`, `menuitemradio` or `menuitemcheckbox` (WCAG 4.1.2, A).
- **Selection.** `selectionMode="single"` makes radio items, and choosing one closes the menu. `"multiple"` makes checkbox items, and the menu stays open so the user can toggle several. Chosen items show a check and a fill, never the fill alone (WCAG 1.4.1, A).
- **Groups.** `MenuSection` names a group for assistive technology. `MenuSeparator` draws a rule.
- **Destructive items.** Put them last, in their own group, and name what they delete.
- **Position.** The menu opens 4px below the button, aligned to its start, and flips at the viewport edge. Its width is capped to the screen minus `space.6` and it scrolls inside the viewport at 320px (WCAG 1.4.10, AA).
- **Contained.** `portalContainer` mounts the open menu in a given element. Omit `trigger` to draw the open list in the flow.
- **i18n.** The label, the section titles and the item labels arrive as props.

## 3. Why the states look as they do

- **Nothing, none, loading, incorrect, done** are n/a. A menu opens on items it already has, and the view reports results.
- **One** is n/a. One action is a button.
- **Some** shows the parts: an icon, a description, a shortcut hint, a disabled item, a destructive item.
- **Too many** scrolls inside the viewport. Typeahead reaches any item.
- **Interaction states** belong to the item. This showcase shows them in a menu, and the menu item showcase holds the reasoning.
- **Selected (single, multiple)** show the check and the fill.
- **Motion.** The list fades and drops 4px in `motion.duration.fast`. Reduced motion keeps the fade.
- **Elevation.** The list is `shadow.1`, the first rung.

## 4. Pitfalls and don'ts

- **Do not use a menu for navigation.** (APG Menu Button; `menu.actions-only`)
- **Do not build the list from divs and click handlers.** (APG Menu Button; WCAG 2.1.1, A; `menu.built-on-aria`)
- **Do not leave the menu unnamed.** (WCAG 4.1.2, A; `menu.labelled`)
- **Do not let the list run off the screen.** (WCAG 1.4.10, AA; `menu.fits-viewport`)
- **Do not write a literal in `menu.css`.** (Bauhaus `misfile.raw-value-in-component`; `menu.no-literal`)
