# Saving and feedback

The Showcase story holds the stage, the save-model decision and four working recipes. The Advisories story holds the live rulebook and the accessibility coverage. The Examples story holds the code of each recipe. This guide holds the reasoning.

## 1. Introduction

**In plain words:** Saving should never be a guess. The page tells you, in one fixed place, whether your work is safe: not yet, in progress, saved, or lost and what to do.

**Precisely:** Pattern. Manual save or autosave, chosen by what the fields do. One page-level save indicator in a status region. A draft for a new record, a leave warning for an existing one. It composes Stack, Icon, Text, Spinner, Button, Banner, TextField, Switch and ConfirmationDialog. It has no style and no token of its own.

**The user need.** A user who edits data must know if the work is safe before they leave (Nielsen heuristic 1, visibility of system status). They must not lose work to a failed request or a closed tab.

**When it exists.** Use it on any screen that edits data: a settings page, a profile form, a long editor, a create form. It sits above components in the import order, so only an app or another pattern may compose it.

## 2. Usage

### Pick the save model

Ask in order and stop at the first answer that holds.

1. **The fields depend on each other.** Manual save. Example: a start date and an end date.
2. **Saving costs money, sends something or has side effects.** Manual save. Example: publish, invoice.
3. **The data has a financial, security or privacy impact.** Manual save (GitLab Pajamas, Saving and feedback).
4. **A setting, a preference or a draft.** Autosave, one field at a time.
5. **Not sure.** Manual save. Pajamas keeps it as the default.

### When not to use, and what to use instead

- **Choosing a message for something other than a save.** Use the Messaging pattern.
- **Field errors before a save.** Use the Form validation pattern.
- **A wait with no save behind it.** Use a Spinner, Skeleton or Progress (`knowledge/patterns/loading.md`).
- **A delete.** Use the Destructive actions pattern.

### How

- **One indicator.** Place it beside the Save button, or in the page header for autosave. Do not repeat it per field and do not raise a toast for a save. One event gets one message (`messaging.one-per-event`). Pajamas places one beside each autosaved input; Bauhaus does not follow that.
- **A status region that stays.** The indicator is a `role="status"` region that is always in the page. Only its content comes and goes. A screen reader then reads the new text and focus does not move (WCAG 4.1.3 Status Messages, AA; APG Alert).
- **Words and icons.** Unsaved changes, Saving…, All changes saved or Saved at a time, Not saved. Colour is never the only cue (WCAG 1.4.1 Use of Color, A). The spinner is `aria-hidden`, because the words already say it.
- **Manual save.** The Save button uses `loading`, never `disabled`, so a keyboard user keeps their place. A second press does nothing. Edits made during the request bring back "Unsaved changes".
- **Autosave.** A click saves at once. Typing saves on blur or 3 seconds after the last key (Pajamas). Only the newest request sets the indicator, so a slow old reply never says "Saved" over a newer save.
- **Failure.** The value stays. The indicator says "Not saved" and offers Retry (Nielsen heuristic 9). After a manual save, focus moves to Retry, because the user waits for the answer. After an autosave, focus stays in the field the user types in (WCAG 2.4.3 Focus Order, A).
- **A new record.** Keep a draft on the device, every storage access in `try/catch`. On return, a Banner "Draft restored" offers Discard (Nielsen heuristic 3). Do not warn on leave: the draft protects the work.
- **An existing record.** In-app navigation with unsaved changes opens a destructive Confirmation dialog "Leave without saving?" with "Leave" and "Keep editing". Focus starts on Keep editing. A tab close uses `beforeunload`, added only while changes are unsaved (MDN, beforeunload event).

## 3. Why the states look as they do

- **Nothing is empty on purpose.** A page with nothing to save says nothing. The region is still there, ready to announce.
- **Loading keeps the button size.** The label hides behind the spinner, so the layout does not jump.
- **None, one, some and too many are n/a.** The indicator is one per page. The number of changed fields does not change it.
- **Incorrect is "Not saved", not an error message.** The fields hold no wrong value: the request failed. Retry is the next step.
- **Correct is n/a.** Valid input before a save is a form-validation state.
- **Done stays.** "All changes saved" stays until the next edit, so a user who looks late still knows.

## 4. Pitfalls and don'ts

- **Do not show a toast for every save.** It competes with the indicator and times out. (Project decision; `saving.one-indicator`)
- **Do not send a request on every keystroke.** (Pajamas; `saving.autosave-timing`)
- **Do not mount the status region together with its text.** It is announced unreliably. (WCAG 4.1.3, AA; `saving.status-announced`)
- **Do not disable the Save button while it runs.** Use `loading`. (Nielsen 1; `saving.manual-guarded`)
- **Do not let an old reply set the indicator.** (Nielsen 1; `saving.latest-wins`)
- **Do not warn on leave when nothing is unsaved.** A question with nothing to protect trains users to click through. (Nielsen 5; `saving.warn-on-update`)
- **Do not keep a `beforeunload` listener when the page is clean.** (MDN; `saving.beforeunload-only-dirty`)
- **Do not autosave money, security or privacy changes.** (Pajamas; `saving.model-by-dependency`)
- **Do not add a stylesheet to the pattern folder.** (`docs/library.md`; `saving.no-own-style`)

## 5. Component gaps

- No save indicator component. Each recipe composes it. When a third screen builds the same indicator, ask for a component.
- No navigation blocker. The app router must block in-app navigation and open the recipe's question.
- No conflict handling. Two users who save the same record need a merge or a "changed by someone else" answer. No source read for this pattern covers it.
