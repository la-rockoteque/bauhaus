# Select

The Showcase story holds the tokens, the stage and the states grid. The Advisories story holds the live rulebook and the accessibility coverage. This guide holds the reasoning.

## 1. Introduction

**In plain words:** A select is a drop-down list. You pick one item from a short list of choices that are already known: a country, a size, a status.

**Precisely:** Component in the fields family. It picks one option from a short fixed list with a native `select`, a visible label, an optional description and an optional error. It is not for a long or searchable list.

**The layer.** A component. The box, label, description and error are shared with the family. The select adds the chevron and the read-only guard.

## 2. Usage

### When to use

- For one choice from a short list that the user knows: fewer than about 15 options.

### When not to use, and what to use instead

- **For two to five options that fit on screen.** A radio group shows all of them at once and needs one click less.
- **For a long or searchable list.** Use the combobox, which filters as the user types.
- **For a yes or no.** Use a checkbox or a switch.

### How

- **Native first.** The component renders a native `select`. The keyboard (Up, Down, Home, End, typeahead), the screen-reader role and the phone picker come from the browser (WAI-ARIA APG Listbox; WCAG 2.1.1, 4.1.2, A). The open list is drawn by the browser and takes its look from the platform.
- **Label, description, error, required.** As the text field (WCAG 3.3.1, 3.3.2, A).
- **Empty choice.** With `emptyLabel` the first option is an empty value that says what to do: "Choose a country". Without it, a value is preselected, and the user may never notice the question. Use the empty choice with `required` so the form can tell "not chosen" from "chosen" (Nielsen heuristic 5).
- **Read-only.** HTML has no `readonly` for `select`. The component sets `aria-readonly` and cancels the keys and clicks that would change the value. Tab still works, so the value stays focusable and readable. If the value must not be reached, use disabled, or show plain text.
- **Disabled options.** Pass `disabled` on an option. Say why nearby.
- **Chevron.** The chevron is an icon hidden from assistive technology. The select keeps its native role.
- **Long labels.** The selected text ellipsizes in the box. The browser list wraps it in full.

## 3. Why the states look as they do

- **Hover, focus-visible, invalid, disabled** follow the text field, because the box is shared.
- **Read-only** has a sunken fill and the default cursor, and it still takes focus.
- **Expanded** is n/a: the browser owns the open list. The combobox draws its own list and shows it.
- **Loading, none, active, selected, done** are n/a. A select with no options should not appear; explain the missing choice in the view.

## 4. Pitfalls and don'ts

- **Do not build a custom select with no keyboard.** (WCAG 2.1.1, A; `select.native-first`)
- **Do not use a select for a long list with no search.** (Nielsen heuristic 6; `select.empty-choice`)
- **Do not show an error by colour alone.** (WCAG 1.4.1, A; `select.error-bound`)
- **Do not leave the label out.** (WCAG 3.3.2, A; `select.visible-label`)
- **Do not write a colour or px literal in the stylesheet.** (Bauhaus `misfile.raw-value-in-component`; `select.no-literal`)
